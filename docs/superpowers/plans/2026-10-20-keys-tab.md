# Keys Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Keys" tab in the settings window to see, add, edit and delete key remaps, applied live.

**Architecture:** Editing logic (draft, clash rule, card text, save/delete/restore) is pure Swift in
`SwipeKeyCore`, tested like `BindingDraft`/`BindingEdits`. `KeyRemapTap` learns to swap its rules
live; `ConfigStore.setRemaps` validates, writes only the `remaps` key, and applies through a hook
`main.swift` provides. The SwiftUI tab and editor sheet reuse `StepBar`, `ShortcutField`, `KeyCap`.

**Tech Stack:** Swift package, SwiftUI/AppKit, XCTest, macOS 13+.

**Spec:** `docs/superpowers/specs/2026-10-20-keys-tab-design.md` (mock-ups in `2026-10-20-keys-tab-mockups/`)

## Global Constraints

- macOS 13+; CI's older Swift compiler: keep expressions simple (see e836372).
- Never touch `~/.config/swipekey/config.json` in tests.
- The config file only changes in its `remaps` key when remaps are edited.
- Loading `config.json` keeps its current rules; the clash rule lives in the window only.
- Double-tap remaps can't have an `app`.
- Tab order: Bindings, Keys, Sensitivity, General.
- Commits only with Mathias's go-ahead: the "Commit" steps below are proposals, batched at the end.

## Review Focus

1. A key held down while remaps are swapped (e.g. Space from Logi held while saving): its release must still be rewritten, so no modifier stays stuck. → Task 2 test `testReplacedRemapperStillReleasesWhatTheOldOnePressed`.
2. A double-tap press held back at the moment remaps are swapped: it must be typed, not lost. → Task 2 test `testFlushTypesTheHeldBackPress`.
3. Two names for one physical key ("return" vs "enter" are different keys, but "@" and its key code "10" are one): clash by resolved key code. → Task 1 test `testClashComparesPhysicalKeys`.
4. A remap list that already clashes (hand-written): the window shows it and refuses to save an edit that keeps the clash, but deleting either works. → Task 1 tests `testExistingClashIsReported` and `testDeleteAlwaysWorks`.
5. First remap added while none was installed at launch, without Accessibility permission: a clear error, nothing written. → Task 3, `setRemaps` applies before writing (manual check in Task 5).

### Task 1: Remap editing logic

**Files:**
- Create: `Sources/SwipeKeyCore/RemapEditing.swift`
- Test: `Tests/SwipeKeyCoreTests/RemapEditingTests.swift`

**Interfaces:**
- Consumes: `KeyRemap` (`from.key/modifiers/app/taps`, `to.key/modifiers`), `KeyPressAction(key:modifiers:layout:)`, `.resolvedKeyCode()`, `.flags`, `ActionSpec.key(_:modifiers:).keyCaps`, `KeyCodes.orderedModifiers`, `KeyCodes.canonicalModifier`, `KeyRemapper`, `DoubleTapper`.
- Produces:
  - `public struct RemapDraft: Equatable` — `key: String?`, `modifiers: Set<String>`, `taps: Int` (1), `app: String` (""), `toKey: String?`, `toModifiers: Set<String>`; `init()`, `init(_ remap: KeyRemap)`; `var remap: KeyRemap?` (nil while incomplete or invalid; app trimmed, empty → nil; taps 2 → app nil); `var error: String?` (why `KeyRemapper`/`DoubleTapper` refuse it).
  - `public enum RemapEdits` — `clashes(with: KeyRemap, editing: Int?, in: [KeyRemap], layout: KeyboardLayout = SystemKeyboardLayout()) -> [Int]`; `save(_: KeyRemap, replacing: KeyRemap?, near: Int?, in: [KeyRemap]) -> [KeyRemap]`; `delete(at: Int, in: [KeyRemap]) -> (list: [KeyRemap], removed: KeyRemap)?`; `restore(_: KeyRemap, at: Int, in: [KeyRemap], layout:) -> [KeyRemap]?` (nil when it now clashes).
  - `extension KeyRemap` — `var title: String`, `var subtitle: String?`, `var fromCaps: [String]`, `var toCaps: [String]`.

Clash rule (spec): same resolved key code, and either remap is a double tap, or (same modifier flags and not (both have an app and the apps differ, case-insensitive)).

- [ ] **Step 1: Write the failing tests** (layout fake: `["@": 10, "a": 12]`)
  - `testDraftBuildsADoubleTap`: key "@", taps 2, toKey "return" → `KeyRemap(from: .init(key: "@", taps: 2), to: .init(key: "return"))`; with app "Logi" typed, the double tap's app is still nil.
  - `testDraftTrimsTheApp`: app "  Logi Options+ " → `from.app == "Logi Options+"`; "   " → nil.
  - `testDraftIncompleteOrInvalid`: no toKey → `remap == nil`; key "nope-key" → `remap == nil`, `error != nil`.
  - `testDraftRoundTrips`: `RemapDraft(r).remap == r` for the Logi remap and the @@ one.
  - `testClashComparesPhysicalKeys`: "@" every press vs from key "10" every press → clash.
  - `testDoubleTapClashesWhateverTheModifiers`: @@ vs ⌘@ every press → clash.
  - `testSameKeyDifferentModifiersDontClash`: "a" vs ⌘a, both every press → none.
  - `testDifferentAppsDontClash`: space from "Logi Options+" vs space from "Other" → none; vs space from any app → clash; app match is case-insensitive.
  - `testEditingDoesntClashWithItself`: `clashes(with: r, editing: 0, in: [r]) == []`.
  - `testExistingClashIsReported`: list [a→b, a→c] → `clashes(with: list[0], editing: 0, in: list) == [1]`.
  - `testSaveReplacesTheOriginalOrAppends`: replacing found by content even when the hint is stale; nil original → appended.
  - `testDeleteAlwaysWorks` and `testRestore`: back at its index; nil when a remap added since clashes.
  - `testCardText`: @@→Return: title "Press @ twice", subtitle "a single @ still types @", fromCaps ["@", "@"], toCaps ["Return"]. Logi: title "Space", subtitle "only when Logi Options+ sends it", toCaps ["⌃", "⌥", "Space"].
- [ ] **Step 2:** `swift test --filter RemapEditingTests` → fails to compile (types missing).
- [ ] **Step 3:** Implement `RemapEditing.swift`. Title of an every-press remap: its from caps joined by " "; of a double tap: "Press \(caps joined by "") twice".
- [ ] **Step 4:** `swift test --filter RemapEditingTests` → all pass.
